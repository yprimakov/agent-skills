Built-in skill loading beats a router skill, for now

I tested two ways to give agents a large skill library without loading every skill into every session. Each setup had 20 sample skills: 5 daily and 15 rare (image, 3D, voice, video and others). Each setup got the same 30 requests.

Result. Both setups picked the right skill on every rare-skill request. The built-in setup (A) took about 40% less time, fewer steps and less cost. The router (B2) saved only about 5 tokens per skill at startup.

Recommendation. Use built-in skillOverrides: "name-only" for rare skills. Give each one a clear, specific name. Add a router only when the rare library grows past several hundred skills.

Context cost as the library grows

This is a straight-line projection from the 15-skill measurement: about 33 tokens per skill with a full description and about 5 with name-only. Real descriptions are often longer than these samples.

At 200 rare skills, name-only costs about 1,000 tokens per session. That is under 1% of a 200k context window. The router saves those tokens, but it adds about 4 seconds and 2 turns each time a rare skill is used.

What went wrong with Router v1

  • Path mix-up. Claude looked for the catalog next to the router file, not in the project folder, so the run failed.
  • Skipped router. On SQL, tax and invoice requests, Claude answered by itself and never opened the router. Its vague description gave Claude no reason to look.
  • The fix needs upkeep. B2 worked because its description lists example domains. That list must change each time you add a new kind of skill.

Limits of this test

  • One run per request and one model (Sonnet). Small differences, like 29 against 30, are noise.
  • The sample skills have clear names. A rare skill with a vague name, such as helper-v2, would hurt setup A more than B2.
  • Each test skill only replies "ACTIVE: name". Real skills add their own work time on top of these numbers.
  • Each test ran in a sealed config with your own skills and plugins turned off, so your setup was not changed.

How to rerun

The harness is in _reports/skill-loading-ab/harness.py in the agent-skills repo: python harness.py build, then build2, then run A and run B2.
